# David Aparicio

**`Backend Engineer · Data Systems · CS '27`**

I'm a backend engineer and a senior studying Computer Science, focused on data intensive systems: APIs, databases, and the infrastructure underneath them. I work in Go and PostgreSQL.

I'm building Resin, an architecture knowledge graph that turns repositories, database schemas, and API specs into a typed, versioned graph, with an MCP server that exposes it to AI coding agents. Before that I built a multitenant RAG backend on Postgres and pgvector, using row level security for tenant isolation and an evaluation harness that blocks any build leaking across tenants or falling for prompt injection.

Previously taught Data Structures & Algorithms weekly to 50+ students as a CodePath Tech Fellow.

 <summary><h3>👨‍💻 David's Coding Journey</h3></summary>

I started with block based coding in middle school, dragging logic blocks around before I had written a real line of syntax. In high school I picked up HTML and CSS to build my first web pages, then JavaScript to make them do something. Going from blocks to markup to an actual language is where I figured out that I liked making things work, not just making them exist.

College is where the depth came. I learned Java and object oriented design, Python for AI and backend work, and SQL for working with data seriously. Somewhere in there I stopped writing scripts that ran on my own machine and started building systems meant for other people: REST and GraphQL APIs, relational schemas, and the database and infrastructure layers underneath an application.

Today I work mostly in Go and PostgreSQL. The difference between now and the kid dragging code blocks is not how many languages I know. It is that I think about tradeoffs first, and about what should exist before I think about how to build it.
